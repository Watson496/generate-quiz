# Agent Skillsでの実装

ここまでに示した作問方針をAgent Skillとして実装します。`SKILL.md`を作問工程の制御に用い、参照資料とPythonスクリプトを工程ごとに呼び出します。作問中の調査記録と最終出力は分け、各判断の完了状態を問題文の版と対応させて管理します。

## 指示の配置と参照順

`SKILL.md`には、作問の前提、各工程で読むファイル、同梱スクリプト、完了条件を記述します。詳しい工程と状態管理は次の参照資料に置きます：

- `workflow_spec.md`：単問・複数問に共通する工程、担当間の受渡し、解答対象ごとの文脈境界に関する規定
- `work_state_spec.md`：題材候補の探索状態、解答対象ごとの作業状態、検査単位に関する規定

作問内容の詳細な規定は、用途に応じて次の3つの参照資料に置きます：

- `selection_and_history_spec.md`：題材選定、重み、履歴に関する規定
- `quiz_generation_spec.md`：問題文の生成に関する規定
- `verification_and_judging_spec.md`：裏取りと正誤判定に関する規定

作問開始時に工程と状態管理の仕様を読み、題材選定前、問題文の作成前、裏取り前、最終出力前に、それぞれ必要な参照資料を読みます。作問規定の全文を`SKILL.md`へ収めず、工程ごとに必要な指示を読み込むことで、一度にコンテキストへ入る情報量を抑えます。

## 複数問の作成

複数問を作る場合は、確定した問題を後続問の題材選定に反映するため、1問ずつ作問工程を完了させます。1問について題材選定、検索、作文、検査、確定、履歴更新までを終えてから、更新後の履歴を使って次の問題を選びます。指定された問題数は、この工程を繰り返す回数として扱います。

各問の工程は、ファセット選択、題材探索、作問、監査、最終出力などのステップに分けます。subagentを利用できる環境では、判断をすべて、ステップごとに起動する担当のsubagentが行います。担当が複数あるステップには統括役のsubagentを置き、担当の起動と、入力・成果物のファイルの受け渡しを任せます。親エージェントはステップを順に進め、確定済み履歴を管理します。親エージェントと統括役は判断を下しません。

担当の種類ごとに、見てよい入力と成果物を担当表で定めます。解答を伏せる検査に解答を渡すといった、入力の組み立ての誤りを防ぐためです。

監査subagentは生成時に示された資料を自ら確認し、不足や反証の可能性がある論点を追加で調査します。生成時の判断をそのまま受け入れることはしませんが、すでに十分な資料が示された論点について同じ支持資料を最初から探し直すこともしません。

個別の解答対象については新しい生成subagentと監査subagentを使います。解答対象を変更した場合は、旧対象の資料、問題文、監査履歴を新しいsubagentへ渡しません。現在の問題が監査に合格して履歴へ加わるまで、次の問題を開始しません。

親エージェントはsubagentの起動時に返された識別子と担当工程を記録し、各成果物が同じ識別子を示すことを照合します。モデルが後から作った任意の識別子は担当記録として使いません。

監査で修正が必要になった場合は、同じ生成subagentが既存の調査結果を引き継いで修正し、同じ監査subagentが変更箇所と影響範囲を再監査します。subagentを再利用できない場合は、確認済みの資料と監査結果を新しいsubagentへ渡します。これにより、問題の修正を行うたびに変更のない論点まで最初から調査し直すことを避けます。

解答露出の検査では、問題文だけを新しいsubagentへ渡し、問題文から自然に生じる名称候補を調べます。この結果は検出の補助に用い、候補に正解が挙がらなかったことだけで露出がないとは判断しません。最終出力は、合格した問題、命題、手掛かり、判断根拠だけを含む限定入力から組み立てます。

subagentを利用できない環境では、親エージェントが同じ状態の境界を保ち、題材探索、生成、露出検査、監査、最終出力の組立てを順に行います。この場合も、現在の問題を確定して履歴を更新してから、次の問題の処理を開始します。

## 分類データの部分取得

題材選定に使う分類データは、索引とファセット別のカタログに変換して`references/`へ配置します。カタログは1ファイルが最大約260KBあるため、通常の参照資料と同じように全文を読み込むことはしません。

`facet_node.py`は、指定した親ノードとその直接の子を一つのブロックとして取り出します。Agentは、子階層へ進むたびに選択したノードのブロックを取得します。これにより、階層をたどるために必要な範囲だけをコンテキストへ読み込みます。

## Pythonスクリプトによる処理

機械的に処理・検査できる部分をスクリプトに任せ、AIによる処理のばらつきや見落としを減らすため、次のPythonスクリプトを同梱します：

- `weighted_pick.py`：重みの正規化、履歴補正、重み付き乱択
- `topic_pick.py`：題材候補の探索状態と抽選対象を照合してから抽選
- `length_check.py`：文字数の計測と許容度による採否判定
- `facet_node.py`：分類カタログから指定したノードを取得
- `work_state_check.py`：作業状態の必須項目、問題文の版、IDの参照関係を検査

`SKILL.md`には各スクリプトの呼び出し方と終了コードの扱いを記述します。入力や呼び出し方に問題がある場合は修正して再実行し、文字数判定が不合格の場合は問題文を改稿して再判定します。確率的な文字数判定では、問題文の各版について抽選値を記録します。監査では同じ値をスクリプトへ渡して判定を再現し、同じ問題文に対して新しい乱数を引くことはしません。

## 実行環境への依存

スクリプトと参照資料は、Skillの配置先を基準とする相対パスで参照します。これにより、Skillを配置するディレクトリが実行環境によって異なっても、同じ構成を利用できます。

このSkillは、Pythonの実行環境とWeb検索手段を必要とします。`SKILL.md`には、それらを利用できない場合に処理を代替せず、作問を中止するように記述します。
