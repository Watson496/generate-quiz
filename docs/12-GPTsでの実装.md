# GPTsでの実装

同じ作問方針を、ChatGPTのGPTsとしても実装しました。作問方針は共通ですが、Agent SkillsとGPTsでは指示と参照資料の読み込まれ方が異なるため、それぞれの実行環境に合わせて構成します。

構成としては、InstructionsとKnowledgeに分け、Instructionsに工程、状態遷移、各段階の完了条件を置きます。Knowledgeには、各判断の詳しい仕様、作業状態の定型、分類カタログを置きます。Instructionsには編集画面の上限として8,000文字の制約がありますが、内容を詰め込みすぎると指示に従わなくなるため、設計目標は6,500文字以内としています。分類カタログは、subjectを最上位コードごとに9分割し、place・time・typeは各1ファイルとしています。

作問中は、題材候補の探索状態と、解答対象ごとの作業状態を分けます。同じ解答対象の修正では確認済みの資料と未解決の指摘を引き継ぎます。解答対象を変更した場合は、旧対象の引用、推論、問題文、監査履歴を新しい作業状態へ引き継ぎません。

問題文を変更するたびに版を更新し、実現命題、構造、表現、解答露出、文字数判定、監査結果を版と対応させます。各判断を共通の検査単位で管理し、生成側の全項目が完了してから監査し、全項目が合格してから最終出力を作ります。最終出力には、合格した項目だけを集めた情報を使い、棄却候補や監査の往復を含めません。

また、スクリプトを同梱できないため、重みの正規化、履歴補正、乱択、文字数の計測と許容度判定、作業状態の確定的な検査にはCode InterpreterのPythonを使います。Agent Skills版でスクリプトが担っていた処理を、その場で実行させます。Pythonの実行に失敗した場合に作問を中止する点は、Agent Skills版と同じです。
