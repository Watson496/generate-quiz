# Agent Skillsでの実装

ここまでに示した作問方針をAgent Skillとして実装します。大まかな方針としては、`SKILL.md`を作問工程の制御に用い、参照資料とPythonスクリプトを工程ごとに呼び出す構成をとります。

## 指示の配置と参照順

`SKILL.md`には、作問工程の順序と、各工程で読むファイルを記述します。詳細な規定は、用途に応じて次の3つの参照資料に置きます：

- `selection_and_history_spec.md`：題材選定、重み、履歴に関する規定
- `quiz_generation_spec.md`：問題文の生成に関する規定
- `verification_and_judging_spec.md`：裏取りと正誤判定に関する規定

題材選定前、問題文の作成前、裏取り前に、それぞれ必要な参照資料を読むように`SKILL.md`で指定します。また、出力直前には3つの参照資料にある必須条件を再確認します。作問規定の全文を`SKILL.md`へ収めず、工程ごとに必要な指示を読み込むことで、一度にコンテキストへ入る情報量を抑えます。

## 複数問の作成

複数問を作る場合は、確定した問題を後続問の題材選定に反映するため、1問ずつ作問工程を完了させます。1問について題材選定、検索、作文、検査、確定、履歴更新までを終えてから、更新後の履歴を使って次の問題を選びます。指定された問題数は、この工程を繰り返す回数として扱います。

各問の生成と監査を別のコンテキストで行うため、subagentを利用できる環境では、問題を作るsubagentと、その問題を反証的に監査する別のsubagentを使います。親エージェントは全体の進行と確定済み履歴を管理し、現在の問題が監査に合格して履歴へ加わるまで、次の問題を開始しません。各subagentには現在の1問だけを担当させることで、指定された問題数をそろえるために、1問ごとの調査、検査、候補の棄却を省略しないようにします。

subagentを利用できない環境では、親エージェントが生成と監査を順に行います。この場合も、現在の問題を確定して履歴を更新してから、次の問題の処理を開始します。未確定の問題を履歴へ加えたり、現在の問題を検査する前に後続問の候補探索を始めたりはしません。

このような複数問の場合にだけ必要となる実行手順は、`multiple_questions_workflow.md`に分けて配置します。`SKILL.md`では、2問以上を指定された場合、題材選定を始める前にこの参照資料を全文読むように指定します。1問だけを作る場合にはこのファイルの指示はコンテキストへ読み込みません。

## 分類データの部分取得

題材選定に使う分類データは、索引とファセット別のカタログに変換して`references/`へ配置します。カタログは1ファイルが最大約260KBあるため、通常の参照資料と同じように全文を読み込むことはしません。

`facet_node.py`は、指定した親ノードとその直接の子を一つのブロックとして取り出します。Agentは、子階層へ進むたびに選択したノードのブロックを取得します。これにより、階層をたどるために必要な範囲だけをコンテキストへ読み込みます。

## Pythonスクリプトによる処理

Agentによる乱択や計数を避けるため、次の処理をPythonスクリプトとして同梱します：

- `weighted_pick.py`：重みの正規化、履歴補正、重み付き乱択
- `length_check.py`：文字数の計測と許容度による採否判定
- `facet_node.py`：分類カタログから指定したノードを取得

`SKILL.md`には各スクリプトの呼び出し方と終了コードの扱いを記述します。入力や呼び出し方に問題がある場合は修正して再実行し、文字数判定が不合格の場合は問題文を改稿して再判定します。

## 実行環境への依存

スクリプトと参照資料は、Skillの配置先を基準とする相対パスで参照します。これにより、Skillを配置するディレクトリが実行環境によって異なっても、同じ構成を利用できます。

このSkillは、Pythonの実行環境とWeb検索手段を必要とします。`SKILL.md`には、それらを利用できない場合に処理を代替せず、作問を中止するように記述します。
