# 複数問を作るときの実行手順

## 目的

複数問の作成でも、各問を独立した作問単位として扱う。後続問を早く完成させる都合で、現在の問題の候補探索、裏取り、作文、検査、棄却を省略しない。履歴補正には、検査を通過して確定した問題だけを使う。

## 共通の不変条件

- 同時に処理中の問題番号は一つだけとする。
- 第n問の処理中に、第n+1問以降の題材候補を挙げない。
- 第n問が全必須ゲートを通るまで、第n問を確定済み履歴へ加えない。
- 第n問を確定済み履歴へ加えるまで、第n+1問を開始しない。
- 不採用候補、未完成稿、監査不合格稿は履歴へ加えない。
- 一つの検索結果を、別々の問題について検索したものとして使い回さない。各問で必要な検索を行う。
- 指定問題数は反復回数として扱い、バッチサイズとして扱わない。

各問について、次の順序で状態を進める。検査後に改稿または再選定した場合は`生成中`へ戻り、合格するまで必要な工程を反復する。

```text
未着手 → 生成中 → 監査中 → 確定 → 履歴更新済み
                  └→ 生成中（改稿または再選定）
```

`履歴更新済み`以外の状態から次の問題を開始してはならない。

## subagentを利用できる場合

親エージェントは問題文や解説を自ら作らず、問題番号、ユーザーの作問条件、確定済み履歴、各subagentの結果を管理する。複数問を並列に生成しない。

### 1. 生成

現在の1問だけを担当する新しい生成subagentを起動する。実行環境がコンテキストの継承範囲を選べる場合は、会話全体を継承しない独立したコンテキストを使う。選べない場合も、総問題数や残り問題数を作業目標として扱わせず、現在の1問以外へ着手させない。subagentへ能動的に渡す情報は次に限る。

- generate-quizを使って1問だけ完成させること
- ユーザーが指定した主題、難易度、長さ等の条件
- 現在までの確定済み履歴、またはその保存先
- 現在の問題に割り当てる番号や保存先が必要なら、その情報

生成subagentは、本スキルの全工程を1問について実行し、全出力項目を備えた候補を返す。後続問には着手しない。

### 2. 独立監査

生成を担当していない新しい監査subagentを起動する。実行環境がコンテキストの継承範囲を選べる場合は、会話全体と生成subagentの推論を継承しない独立したコンテキストを使う。選べない場合も、生成時の説明を監査の根拠に使わせない。監査subagentには候補の問題・解答・付帯情報、ユーザーの条件、本スキルと必要な参照仕様を渡す。

監査subagentは候補を擁護したり書き直したりせず、不成立または仕様違反となる具体的な反例を探す。Web検索を使い、少なくとも次を再検査する。

- 問題文から正答・別解を語形成、翻訳、同義置換だけで作れないか
- 正答または別解の固有部分が問題文に露出していないか
- 問題文中の語と回答断片を連結しなければ名称が完成しない正答範囲になっていないか
- より短い自然な正答、別名、同義語、表記が漏れていないか
- 同じ手掛かりに同程度に当てはまる対抗候補がないか
- 各手掛かりが対象全体を中核的かつ準一意に特徴づけているか
- 中核性の根拠が、資料内の掲載位置や資料作成主体による呼称の限定ではなく、解答対象自体の理解における位置を示しているか
- 初学者側の難易度根拠が、教材への名称・事例の出現だけでなく、対象読者、教材内での役割、学習上の位置、問題が要求する知識の粒度まで支えているか
- 命題理解に意味内容の知識が必要な専門用語が一つずつ抽出され、想定層が各用語を明白に理解できる根拠と推論があるか
- 連体修飾、連用中止、係り受け、作用域、読み上げ順が規定を満たすか
- 問題文の全命題と正誤判定を、出典が実際の強さと射程で支えるか

監査結果は、`合格`または`不合格`を先頭に置く。不合格なら、該当する問題文または出力欄、破っている規定、反例または根拠を具体的に示し、次のどちらに当たるかを区別する。

- 記載不足：判断を支える資料と推論は成立するが、必要な引用、所在、対応関係、推論が候補出力に欠けている。
- 判断不成立：資料の対象・役割・範囲・粒度が結論に届かない、反例が残るなど、出力の補記だけでは合格にできない。

### 3. 確定または再処理

監査が合格なら、その候補だけを確定し、履歴へ加える。監査が不合格なら履歴へ加えず、生成subagentへ具体的な指摘を渡して同じ1問を再処理させる。記載不足は必要な引用、所在、対応関係、推論を補う。判断不成立は追加調査を行い、なお根拠が結論に届かなければ問題文を改稿するか候補を棄却する。改稿によって題材候補の必須ゲートを満たせない場合は、候補を棄却して題材選定からやり直す。補記または改稿後の候補も、新しい監査subagentで監査する。

確定済み履歴の更新が終わった後に限り、次の1問の生成subagentを起動する。

## subagentを利用できない場合

複数問の依頼を中止しない。親エージェントが、現在の1問だけを対象として次を順に行う。

1. 確定済み履歴を使って題材を選ぶ。
2. 候補探索、裏取り、作文、文字数判定を行う。
3. 作問時の説明を参照せず、完成稿から実現命題と正答範囲を取り直す。
4. 独立監査と同じ反証項目を一つずつ検査する。
5. 不合格なら、同じ題材を改稿できる場合は2からやり直し、題材を棄却する場合は1へ戻って再選定する。
6. 合格した問題だけを確定して履歴へ加える。
7. 履歴更新後、次の問題について1へ戻る。

現在の問題が`履歴更新済み`になるまで、後続問に関する思考、検索、下書き、ファイル作成を行わない。進捗をユーザーへ伝える場合も、未着手の後続問について予定題材を示さない。

## 終了条件

確定して履歴へ加えた問題数がユーザーの指定数に達したときだけ完了とする。監査不合格、裏取り未完了、未確定、欠番の問題を問題数へ数えない。
