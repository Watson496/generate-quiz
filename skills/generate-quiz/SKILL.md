# 役割

日本語の競技早押しクイズを新規作成する専用スキルである。ユーザーの明示的な指定は、以下の既定値・既定規則より常に優先する。ただし、複数問を直列に確定して履歴を更新する実行順は、履歴補正を成立させるための前提であり、作問条件によって省略・並列化しない。指定が両立不能でない限り事前質問をせず、直ちに作問する。明示的な改稿依頼では題材を差し替えず既存問題を改稿し、履歴上も最終版で旧版を置き換える。

`references/` の各仕様は任意参照の背景資料ではなく、毎回必ず適用する規範である。記憶や一般知識で代替せず、後述の参照順に従って該当ファイルを実際に読んでから判断する。

以下 `$SKILL_DIR` はこのスキルのディレクトリを指す（個人スキルとして入れた場合は `~/.claude/skills/generate-quiz`）。

# 複数問の実行単位

問題数の指定は、1問の作問工程を繰り返す回数であり、一括生成の単位ではない。2問以上を作る場合は、題材選定から検査、確定、履歴更新までを1問ずつ完結させる。第n問を確定して履歴へ加える前に、第n+1問の題材候補を選んだり、検索・作文・検査を始めたりしない。複数問分の候補探索、Web検索、問題文作成、検査をまとめて行わない。

subagentを利用できる環境では、親エージェントは複数問全体の進行と確定済み履歴だけを管理し、各問の生成と独立監査を別々のsubagentへ委ねる。subagentを利用できない環境では、親エージェントが同じ境界を保って1問ずつ処理する。いずれの場合も、複数問の詳しい手順は題材選定を始める前に [`references/multiple_questions_workflow.md`](references/multiple_questions_workflow.md) を全文読み、そのとおりに実行する。

# 既定値

- 問題数：1問
- 主題：指定がなければファセットと履歴から重み付き乱択
- 難易度：当該分野を継続的に学び始めて1〜2年以内の人には基礎・概説知識として正答を期待できる一方、その分野を特に学んでいない一般的な日本語話者には通常は正答を期待しにくい水準
- 長さ：80文字付近の許容度を最大とし、典型的な広がりがおおむね20文字、長い側にやや裾を引く分布
- 構文：題材と正答範囲に応じたSC型またはOV型

# 必須ツール

- **裏取りは毎問 WebSearch（必要に応じて WebFetch）で行う。** 検索を省略して内部知識だけで命題を確定しない。検索手段が一切使えない場合は作問を中止し、その旨を伝える。
- **重み付き乱択・履歴補正・文字数計測と許容度判定は、必ず Bash から `scripts/` の Python を実行して行う。** 暗算・目測・概算で代替しない。
  - ファセット／候補の抽選：`scripts/weighted_pick.py`
  - 文字数と採否：`scripts/length_check.py`
  - ファセットノードの取得：`scripts/facet_node.py`
- 各スクリプトの終了コードは `0` が正常、`1` が「該当なし（`facet_node.py`）／改稿が必要（`length_check.py`）」、`2` が入力・引数の不備である。`2` は自分の呼び出し方の誤りなので、修正して再実行する。
- `python3` の実行に失敗したら再試行し、それでも失敗した場合は作問を中止する。ユーザーが明示的に許可した場合に限り、あなた自身による擬似的な重み付き選択へ切り替える。乱数シードは設定・表示しない。
- 内部の weight、コード、抽選過程、不採用候補、予定命題台帳、スクリプトの生出力はユーザーへ表示しない。

# 参照順

1. 題材選定前に `references/selection_and_history_spec.md` と `references/facet_index.md` を Read し、必要なファセットカタログの該当親ブロックを `scripts/facet_node.py` で取得する。
2. 候補品質判定・作文前に `references/quiz_generation_spec.md` を Read する。
3. 裏取り・別解・正誤判定・出典作成前に `references/verification_and_judging_spec.md` を Read する。
4. 出力直前に三仕様の全必須ゲートを再確認する。

`references/facet_*.md` のカタログ本体は最大約260KBある。**Read で全文を読み込まない。** 必ず次の形で必要なブロックだけを取り出す。

```bash
python3 "$SKILL_DIR/scripts/facet_node.py" 'subject::7'          # 親ブロックとDIRECT_CHILDREN
python3 "$SKILL_DIR/scripts/facet_node.py" --children 'place::(1/9)'
python3 "$SKILL_DIR/scripts/facet_node.py" --grep '音楽'          # ラベルからNODE_KEYを探す
```

カタログにない分類ノード、コード、階層、出典情報を推測して作らない。

# Web検索による検証

問題文、解答、難易度の両参照集団、中核性・代表性、準一意性、手掛かりの強さについて、外部検証可能な結論をWeb検索で得た出典記述と対応させる。出典の直接記載、演繹、解釈、複数資料の総合を区別し、必要な推論を明示する。内部知識、印象、検索件数・順位、資料不在だけで合格させない。十分な資料上の根拠を得られなければ候補を棄却する。

# 題材選定

`subject → place → time → type` の順に選ぶ。各ノードで、まず題材領域の意味・広さ・既定難易度との両立から細分化するか停止するかを判断する。停止判断に履歴補正を使わない。細分化すると決めた場合は、親の直接の子を漏れなく比較し、現在の文脈における基礎local weightを推定し、履歴補正後の重みで `weighted_pick.py` により抽選する。

基礎weightは日本語圏での文化的共有度、多様なコミュニケーション場面での重要性、文化的背景知識としての機能を中心に、sibling group内の相対比として判断する。検索順位、作問・裏取りの容易さ、生成後の品質をweightへ混ぜない。

抽選は次の形で行う。`base_weight` は自分で推定した正の実数（丸めない）、`history_distances` は「何問前にそのノードが選ばれたか」（直前が1）の一覧である。

```bash
cat <<'JSON' | python3 "$SKILL_DIR/scripts/weighted_pick.py"
{"candidates": [
  {"key": "subject::78", "label": "音楽", "base_weight": 3.2, "history_distances": [2]},
  {"key": "subject::79", "label": "レクリエーション．娯楽．スポーツ", "base_weight": 2.4}
]}
JSON
```

選択領域から具体的な解答候補を内部知識と候補発見用Web検索で広く集める。固定件数を目標にせず、新しい有力候補がほぼ増えないところまで探索する。同一対象を統合し、履歴・難易度を反映した相対weightで同じスクリプトにより抽選する。選ばれた候補が品質ゲートを満たさなければ、`--exclude <key>` を付けて再抽選する。

# 履歴

同じ会話で実際に出力した問題と、ユーザーが渡した問題・解答・題材リストを履歴に使う。同一の複数問依頼を処理している間は、全必須ゲートを通過して確定した未出力の問題も、後続問の履歴に含める。外部履歴は指定がなければ上から古い順、末尾を最新と読む。ユーザーが履歴ファイルのパスを渡した場合は、それを Read して同じ扱いで取り込む。

ファセットの各sibling選択には、直近に選ばれた同一ノードほどweightを下げ、時間とともに現在の基礎weightへ戻る補正を、subject等の文脈をまたいで掛ける（`w_j = b_j × Π min(1, d × p_j)`。`weighted_pick.py` が実装する）。最終問題で実質的に扱った副経路も主経路と同じ強さで履歴化するが、表示するのは選択時の主経路だけである。

過去問と同一・同義・包含・含意・実質的に同じ手掛かりとなる命題を再使用しない。固有性の高い人物・作品・事件等は、独立命題であっても自然な出現比率に応じて数百〜数千問規模で再出現を抑える。調査中に見ただけの情報や不採用候補は履歴に加えない。改稿後は旧版を最終版で置き換える。

# 題材候補の必須ゲート

成文化前に、入門・概説資料等を史料批判的に調べ、解答対象そのものを紹介する中核情報を特定する。その情報が初学者には基礎的だが一般層には通常知られず、対象・名称との間に対象固有の非自明な対応があることを要する。代表説明から解答名を容易な語形成・翻訳・同義置換だけで作れる候補、非自明な知識が別の人物・対象当てへほぼ縮約される候補は棄却する。ただし対象全体に固有の別の中核的・非自明な出題意図が成立するなら採用できる。
中核情報を使うと一般層にも容易すぎる題材を、珍しい逸話・特殊な数値・最近の出来事だけで人工的に難化しない。

# 手掛かり単位と情報選択

作文前に、予定する情報を「意味上自立する最小の情報パッケージ」である手掛かり単位へ分ける。複数の原子的命題が、共通する一つの述語・出来事・関係枠組みのもとで一つの特徴を共同して表す場合だけ一単位にできる。独立した述語・性質は、同じ核名詞へ係っても別単位とする。
各単位についてWebで、最も近い自然な上位分類を主たる比較群とし、現実的な上位分類・交差分類も加える。分類側から同種対象を探すとともに、手掛かりの性質から逆向きにも候補を探し、得た有力候補の和集合と比較する。各単位は、ほかの単位に依存せず、対象理解における中核性と実用上の準一意性を持たなければならない。有力な近接候補が同程度に残る単位は不合格とする。
単位内の各命題は特徴づけに実質的に寄与し、各単位もほかの単位にはない情報を加える。同義反復、包含・含意、抽象度だけを変えた反復、削除しても中核的理解・識別・出題意図がほぼ変わらない情報を残さない。
完成稿を実際の統語・意味・読み上げ上のまとまりで再分割し、全単位を再検査する。不合格単位は削除・差し替え・自然な一関係への再構成を行う。弱い情報を字数のために残さない。削除後は別の有効情報を探し、なければ文字数分布を再評価し、許容できなければ題材全体を棄却する。

# 命題台帳と問題文

作文前に、問題文へ入れる基礎事実・関係・限定を必要十分な「予定命題」として平叙文で書き、各複合命題の全真偽条件を確認する。異なる述語・関係として独立に真偽評価できる内容は、同じ一文・連体修飾節に含まれていても別命題にする。完成文へ解答を埋めた一文を、そのまま一命題として掲げない。因果・契機・継起・対立等は基礎事実とは別の関係命題として扱うが、単なる論理的帰結を際限なく増やさない。`検証要素`は一つの述語・関係内部の主体・対象・場所・部位・時点・条件等だけに用い、複数の述語・関係を一命題へ束ねる代用にしない。
作文前に各予定命題の述語・関係ごとに、主体、対象・目的語、場所、起点・到達点、部位、時点・期間、条件・目的、指示対象等の項構造を整理する。
成文化後は、予定命題や作問意図を参照せず、疑問詞を解答で埋めた完成稿から「実現命題」と項構造を表層に忠実に再抽出する。許される正規化は、主語補完、指示語展開、並列項への共通述語補充等、真偽条件を保存するものだけである。格、述語、時制・相、条件、否定、数量、範囲、確実性、因果・契機・対立、集合と構成員等を変更・脱落・善意に修正しない。
各連体修飾節は、被修飾名詞を補った局所命題へ戻す。被修飾名詞・述語の項・全体と部分の射程を保ち、`巡礼路`を`巡礼`、著作を著作中の一節等の関連対象へ置き換えない。各独立手掛かりについて、局所命題と、手掛かりを含む核名詞句による特徴づけ命題を別々の命題として内部的に立て、前者の真だけで後者を合格させない。局所内容の存在だけでなく、対象全体をその内容で特徴づける中核性・代表性があるかを検査し、著名な一部分であるだけでは合格にしない。不適切なら部分関係を明示する改稿、差し替え、削除を比較して全ゲートをやり直す。

各手掛かりでは、事実の種類（一回的な個別事実、少なくとも一例の存在、反復・継続、作風・傾向、評価・知名度）と、その事実の中核性・代表性を別軸で検査する。一回的事実でも代表的業績なら採用でき、反復的事実でも周辺的なら棄却する。最終述語は資料が支える回数性・相・評価性と一致させる。不定の作品群・活動類型を作風や傾向として採用するのに、一例の存在しか表さない`制作した`等で済ませない。傾向・評価を裏取りできなければ、具体的な個別業績へ改めるか手掛かりを棄却する。
全文として意味・係り受け・真偽条件の異なる複数の自然な読みを許す完成稿は不採用にする。予定命題と実現命題、および予定・実現項構造を双方向に照合し、主体、格、場所句の係り先、部位の所属、指示対象、作用域を含む漏れ・余分な主張・意味の変更があれば、問題文を改稿して抽出からやり直す。項構造検査は自然な日本語を作るための補助的な安全網であり、表を埋めること自体を目的にしない。

必ずSC型またはOV型で、一つの対象または名称を答えさせる。列挙問題、年・数値・数量そのものを答えさせる問題は既定では作らない。情報を担う節は核名詞句へ収束する連体修飾部に収め、文全体に係る独立前置き節、重文、「ですが」構文を使わない。
複数の独立属性は通常、各々の連体形で核名詞へ係らせる。連用中止は、並列・継起・理由・対立等が実際に成立し、その関係を表す日本語として自然な場合だけ使う。
落としとなる終端部分は、中核性と準一意性を備え、対象が端的に何であるかを直接説明する。付随的な数値・性質・逸話だけで終えず、解答対象と同じ抽象度・射程にする。前フリにも同じ中核性と準一意性を要求する。
名称等の属性を対象本体へ帰属させない。自然な日本語と、読み上げ順に無理なく意味を理解できることを最優先する。後続語で先行する長い部分を不必要に大幅再解釈させない。前置表現が後続名詞を限定するのか、述語・事態全体の成立領域を限定するのかを区別し、修飾形式と作用域を一致させる。情報順は文脈上の手掛かりの強さを比べ、弱いものから強いものへ進める強いヒューリスティックとするが、日本語・命題関係・落としを優先する。
独立前フリとして置く連体修飾節は、通常の読み上げで、対象について一つの事実を累加的に述べる叙述として明確に聞こえなければならない。後続名詞句を選別する限定条件としても自然で、叙述的提示を積極的に確認できない場合は、そのまま通さず再構成・移動・差し替え・削除する。作文前は短く音声的に軽い節等を警告し、完成稿でハードゲートを適用する。落としはこのゲートの対象外とし、水増しや意味関係の成立しない連用中止で救済しない。
書面・音声の双方で、解答や識別力の高い部分を露出させず、容易な変換だけで復元できる問題にしない。問題文には読み仮名を付けない。

# 正誤判定と問題成立性

問題文候補を作ったら、その文脈で○となる最短の自然な回答形式を先に定める。回答表現自体が標準名称、確認済みの別名、慣用的省略等として自然に対象を指す必要がある。問題文中の語と回答断片を連結して名称を完成させない。問題を成立させるためだけに完全名称や不要な限定を要求しない。
その正答範囲を前提に、正答へ必要な非自明な知識が解答対象全体に固有の中核的対応かを再検査する。より単純な別対象を問う問題へほぼ縮約される、または名称が代表説明から自明に生成できるなら棄却する。

# 裏取り・引用

問題文、解答、読み、原語表記、別解、正誤判定、一意性、時点情報を命題単位で検証する。資料数は固定せず、来歴・本原性・独立性・射程を評価し、反証・異説・例外・対抗候補を探す。検索スニペットだけで確定しない。
各実現命題について、その真偽条件を生じさせる問題文の必要十分な原文箇所を逐語引用する。一つの述語・関係内部に複数の真偽条件を含む命題だけ「検証要素」を示し、全要素を検証する。主体の切替え、格関係、場所句の係り先、部位の所属、指示対象、作用域を誤りやすい複雑な命題では、必要な項構造も同じ欄に示す。各命題には、証拠力の高い出典の該当記述を必要最小限、所在情報付きで直接引用する。非連続箇所は別引用とし、連続箇所の省略は`〔中略〕`、引用者補足は`〔〕`で示す。体裁上の改行除去・明白な行末ハイフネーション復元以外は原文を黙って変更しない。
外国語資料は原文を示し、必要時は対応する既存の公認・刊行訳を優先して別出典として示す。適切な既存訳がなければ`〔AI訳：……〕`とする。印刷ページを主とし、ずれがあるPDFは`PDF p.`を補助併記する。年不明は`n.d.`とする。
直接確認・二次資料による間接確認・参照候補で内容未確認を区別し、複合命題と問題全体の状態は最も弱い必須要素に合わせる。出典の直接記載、確認済み前提からの演繹、解釈・総合も区別する。調査行為を「資料Aが支える」「〜と判断した」と報告するだけで済ませず、出典の実際の記述、前提、推論、射程を論証する。単純命題は引用と所在だけでよく、検討が必要な場合だけ分析を加える。資料に合わせて実現命題を修復せず、問題文を改稿して再検査する。

十分な裏が取れなければ、証拠の射程に合わせて問題文を改稿し、なお成立しなければ題材を棄却する。未電子化文献の扱いと条件付き採用は `references/verification_and_judging_spec.md` に従い、未確認命題・候補文献・関連付けの根拠・現物確認事項を明記する。

# 文字数

まず特定の目標値を固定せず、自然な80文字付近の初稿を作る。「問題：」を除く本文を `length_check.py` へ渡し、NFC正規化した文字数と `quiz_generation_spec.md` の許容度曲線による採否を得る。

```bash
python3 "$SKILL_DIR/scripts/length_check.py" '……を何というでしょう？'   # 既定（ソフト）
python3 "$SKILL_DIR/scripts/length_check.py" --max 60 '……でしょう？'    # 以内・以下・厳守
python3 "$SKILL_DIR/scripts/length_check.py" --target 100 '……でしょう？' # 前後・程度・くらい
```

`VERDICT REJECT`（終了コード1）なら、原則として同じ裏取り済み命題だけを使い、長さの異なる自然な言い回しへ改稿して再計測する。文字数合わせの情報追加・削除をしない。数回の自然な改稿でも通らない場合は、品質の最も高い候補を採用する。

「以内・以下・ちょうど・範囲内・厳守」はハード制約として `--max/--min/--exact` で確認し、「前後・程度・くらい・短め・長め」はソフト目標として `--target` で扱う。ハード制約を品質を保って満たせなければ、条件外の問題を黙って出さず、その旨を伝える。

文字数調整を含む改稿後は、実現命題と項構造の再抽出・予定命題および予定項構造との双方向照合、全手掛かり単位の再分割・品質検査、正答範囲を前提にした問題成立性の確認をやり直す。
